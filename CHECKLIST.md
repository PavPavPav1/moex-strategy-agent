# Чек-лист перед сдачей

Проверено на проекте MOEX Strategy Agent. Статусы относятся к воспроизводимому демо `moex-agent demo --cache-only --fault backtest_moex_strategy=timeout` и тестам `pytest`.

## Чек-лист из лекции 2

- [x] **Описание каждого инструмента проходит тест стажёра.** Есть глагол в имени, назначение, когда использовать/не использовать, границы, формат результата и отличие от соседнего инструмента. Восемь полей каждой карточки — `docs/tool_contracts.json`.
- [x] **Аргументы проверяются по схеме, ошибка возвращается модели.** Pydantic `extra=forbid`, диапазоны дат/окон/`top_n`, ошибки `type/message/hint/retryable`. Тесты `test_validation_error_is_regular_result`, `test_rejects_inverted_windows`.
- [x] **То, что известно коду, не выбирается моделью.** В проекте нет клиентского счёта. Спецификация и состояние хранятся в `AgentSession`; URL ISS, TQBR, интервал 24, каталоги, RSS и лимиты задаёт код/конфиг. Поле «что не от модели» есть в каждой карточке.
- [x] **Таймаут сервиса не роняет агента.** `ToolExecutor` делает не более двух попыток только для `retryable`, возвращает структурированную ошибку. `MOEXClient` может использовать точный маркированный кэш. Тесты временного/постоянного таймаута и живое демо с `--fault` пройдены.
- [x] **Результат ограничен по размеру.** Максимум 12 000 символов в контексте, 5 сделок в preview, 10 движений, 3 новости на движение, 100 записей на RSS и 300 всего. Полные данные — в CSV, а не в контексте.
- [x] **Есть лимит шагов.** `max_steps=6`, максимум 12 в коде, два вызова на шаг и остановка при третьем одинаковом вызове подряд. Тест `test_loop_guard_stops_third_identical_call`.
- [x] **Действие выполняется только после подтверждения человеком.** Неприменимо по архитектуре: опасных действий нет. Все три инструмента `read_only`; агент не подключается к брокеру и не размещает заявки.
- [x] **Провайдер задан в конфиге, ключей нет в репозитории.** `provider`, `model`, `base_url`, `api_key_env` — `config/agent.json`; `.env` исключён, `.env.example` без значения. Живой GigaChat не проверялся без токена.
- [x] **На демо видна ошибка инструмента и выход из неё.** Команда с `--fault backtest_moex_strategy=timeout` выводит `timeout → технический повтор → восстановлено`; события `tool_error(will_retry=true)` и `tool_result` видны в `reports/demo_sber/trace.jsonl`.

- [x] Используются исторические дневные данные MOEX ISS с пагинацией и контролем целостности.

## Осознанные ограничения

- Поддерживается только дневная long-only стратегия пересечения двух SMA на TQBR.
- Не моделируются налоги, дивиденды, лоты, проскальзывание и ликвидность.
- Прямой сетевой запуск зависит от доступности внешних сервисов; гарантированно воспроизводимый режим — `--cache-only`.
- Один тикер/период не доказывает устойчивость стратегии; следующий шаг — walk-forward и out-of-sample.
